The database behind the loop

16 tables in four groups. The Studio defines who to reach, the 03:00 nightly run scores them and builds care plans, and the portal records calls and actions. Outcomes are read back by the next nightly run. Sample rows follow one demo story: Layla creates a graph feature, the cohort and campaign pick up Priya, and Nadia calls her.

Studio · Cohorts writes features, cohorts, campaigns→ Nightly 03:00 writes feature values, signals, scores, care plans→ Studio · Care intelligence writes the call list→ Care portal writes contacts, actions, outcomes↩ outcomes read by the next nightly run

Clinical source data stays in the knowledge graphClaims, labs and devices are queried there, read-only. This database keeps only derived values (member_feature) and what the care team does.
One care-plan need = one actionaction.need_id points at a care_plan_need. Closing either one updates the other in the same transaction and writes an outcome.
Outcomes are the only way backThe portal never edits signal or risk_score. It inserts outcome rows. The nightly run reads the unprocessed ones and stamps processed_at.
